# 调研报告：全球鱼类贴纸库可行性（2026-11-19）

本报告列出需求文档 v0.2 依据的每一条事实，以及它是怎么验证的。探测脚本和原始结果在 [`research/`](../research/)。

## 1. 结论先行

| 问题 | 结论 | 把握 |
|---|---|---|
| 有没有可商用的全球鱼类分类骨架 | **有**。Catalogue of Life 2026-11-11 版（CC BY 4.0）收录了 FishBase 提供的分类，在 COL 里标注为 CC BY | 97% |
| 一共多少种 | COL 中现生鱼类 **38,184 个接受种**，其中约 300 个带灭绝标记；Catalog of Fishes 公布 37,799 个有效种。规模约为鸟类的 3.5 倍 | 97% |
| 中文名够不够 | Wikidata 上关联了 FishBase 编号的条目有 35,018 个，其中 **27,724 个有中文标签**（CC0） | 90%（数量已核实，准确性需抽检） |
| 英文名够不够 | **不够**。Wikidata 上只有 8,930 种鱼有英文俗名；很多鱼本来就没有英文名。FishBase 的英文名禁止商用 | 95% |
| 参考照片够不够 | **这是最大的风险**。随机抽 150 种：只有 53% 能在 iNat 或 Commons 找到开放授权的照片；**37% 一张 CC 照片都找不到**（鸟类版只有 3.6% 没参考照）。加上 GBIF 和论文插图后，开放授权来源覆盖到 81%，但补进来的几乎全是福尔马林标本照，体色不可信 | 90% |
| 中国鱼类会不会好一点 | 只好一点。在 GBIF 上有中国记录的 4,528 种里抽 100 种：开放授权来源覆盖 74%，iNat 开放授权照片只有 32% | 85% |
| CDN 能不能用 | jsDelivr 单文件上限 20 MB，仓库大小不影响按文件加载（实测鸟类仓库 700 MB 能正常加载）。鸟类仓库 42 MB 的 `species.json` 在 jsDelivr 上返回 403 | 98% |
| 仓库会不会太大 | 3.8 万张 × 约 60 KB ≈ 2.3 GB。GitHub 建议 1 GB 以内、强烈建议 5 GB 以内；单次推送上限 2 GB；**单个文件超过 100 MB 直接被拒** | 98% |
| AI 能不能把鱼画对 | **纸面调研没法回答**。公开资料普遍指出，生图模型在鳍条数、鳍的位置、脂鳍、侧线、鳞片上容易出错。只能靠试画来量 | 50%，要试画才能提高 |
| 要花多少钱 | 只能给范围：约 13 万次生图，按每张 \$0.017–0.20 算，约 \$2,300–27,000，再加审核调用。要试画才能缩小范围 | 60%，要试画才能提高 |

## 2. 证据明细

### 2.1 分类与物种数
- Catalogue of Life 发布版：ChecklistBank dataset `317005`，版本 2026-11-11，授权 `cc by`。鱼类部分的来源是 dataset 1010（FishBase，版本 2026-11-01），在 COL 里的授权也是 `cc by`。
- 各类群接受种数（COL API 实查）：

| 类群 | 种数 |
|---|---|
| 辐鳍鱼（Actinopterygii） | 36,672（含 289 个灭绝标记） |
| 板鳃类（鲨、鳐） | 1,303 |
| 全头类（银鲛） | 59 |
| 盲鳗 | 93 |
| 七鳃鳗 | 49 |
| 肺鱼 | 6 |
| 腔棘鱼 | 2 |
| **合计** | **38,184** |

- 生境标记（辐鳍鱼部分）：淡水 19,301，海水 18,098，半咸水 3,502。一个种可以有多个标记。
- Catalog of Fishes：37,799 个有效种，版权归加州科学院，**不是开放授权**，只能用来核对。
- COL 里鱼的俗名很少，例如眼斑双锯鱼只有一个日文名。俗名要从 Wikidata 取。

### 2.2 名字与编号（Wikidata，CC0）

| 指标 | 数量 |
|---|---|
| 有 FishBase 编号（P938）的条目 | 35,018 |
| 有中文标签，且标签里确实有汉字 | 27,724 |
| 有日文标签 | 2,062 |
| 有英文俗名（P1843） | 8,930 |
| 有 IUCN 等级（P141） | 24,253 |

- 中文名大多来自中文维基的鱼类条目，这批条目的命名常沿用台湾的鱼名体系，和大陆习惯名可能不同，需要抽检。
- 台湾鱼类资料库和《拉汉世界鱼类系统名典》在网上公开的内容多为 CC BY-NC，**不能整体搬**。
- 《中国生物物种名录》部分发布版本是 CC BY-NC，也不能整体搬。

### 2.3 参考照片（实测）

**全球随机 150 种**（脚本：`ref_probe.py`、`ref_probe2.py`）

| 来源 | 至少有 1 张的比例 |
|---|---|
| iNat 研究级观察、开放授权（CC0/BY/BY-SA） | 21% |
| iNat 观察、任意 CC 授权（含 NC） | 48% |
| Wikimedia Commons 文件 | 50%（按文件搜索计，可能有误匹配） |
| iNat 开放授权或 Commons | 53% |
| GBIF 开放授权图片 | 63% |
| 论文插图（Biodiversity Literature Repository） | 41% |
| 以上任意开放授权来源 | 81% |
| 什么都没有 | 16% |

- 在 iNat 和 Commons 上都找不到、要靠 GBIF 补上的 18 种里，**17 种只有标本照**（`PRESERVED_SPECIMEN`）。
- 找不到照片的种集中在这几类：深海鱼（巨尾鱼科、长尾鳕科、绵鳚科）、南美小型脂鲤和鲶、非洲慈鲷、小型虾虎鱼。

**中国随机 100 种**（脚本：`cn_probe.py`）
- iNat 开放授权 32%，Commons 52%，GBIF 开放授权 71%。
- 任意开放授权来源 74%；算上 NC 授权是 80%。

**推论**：要做到图鉴级体色，需要活体彩色照片。按开放授权算，大约只有一半物种能找到。**这是和鸟类版最大的不同，直接决定首发范围和质量策略。**

### 2.4 参照项目的实际情况
- 鸟类版从 v0.1（2026-10-31）到全部过线（2026-11-09）只用了约 10 天。但它前期已经为鸣迹 App 积累过一批贴纸。
- 作者公开说消耗了 10 亿以上 token，用掉 1 次 Claude Code 的 \$200 周额度和 3 次 Codex 的 \$200 周额度，主要靠代理调用生图工具，而不是按张付 API 费。
- 首版 11,064 张里只有 7,676 张过线，没过线的保留了最高分那一版先发布。后来按更严的标准重审，几乎全部重画了一遍。
- 争议：鸟友和科普作者批评 AI 贴纸可能“污染”科普内容和 iNat 这类公民科学数据。鱼类版要在 README 里明确提醒，不要把贴纸当作观察照片上传。
- 鸟类版约有 2,500 张贴纸的参考照是 NC 或保留所有权利的。它的处理方式是“照片不分发，只记出处，按授权分类统计，提供撤图通道”。

### 2.5 分发限制
- jsDelivr：单文件上限 20 MB；GitHub 仓库按文件加载可以正常使用。第一次请求偶尔会返回 403，重试就好（实测）。
- GitHub：单文件超过 100 MB 拒收；单次推送上限 2 GB；仓库建议 1 GB 以内，强烈建议 5 GB 以内。
- **推论**：鸟类版 `species.json` 是 42 MB，鱼类版照比例会到约 145 MB，**超过 GitHub 上限**，必须拆分。

### 2.6 生图费用参考（2026-11 公开价格，需以官方为准）
- OpenAI GPT Image 2.x：按 token 计费，中等画质每张约 \$0.03–0.05，高画质约 \$0.08–0.21；批量接口打五折。
- Gemini 图像模型：1K 分辨率每张约 \$0.034，批量约 \$0.017；单次请求最多可以带 14 张参考图。

## 3. 只有试画才能回答的问题

| 问题 | 试画怎么回答 |
|---|---|
| 生图模型能不能稳定画对鳍的位置、脂鳍、尾鳍形状、须 | 30 种 × 3 次，人工逐张核对 |
| AI 审核员能不能发现这些错误 | 人工复核同一批图，算出审核员的漏判率和误判率 |
| 只有标本照或只有文字描述时，能画到什么程度 | 试点里专门放 10 种这样的鱼 |
| 平均几次过线、单种成本多少 | 由前三项直接算出 |
